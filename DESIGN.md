# PHPBench workload design

## Workload identity and source

- Zathras selects `--sub_test phpbench` in `config/test_defs.yml` test19.
- The selected PTS profile in the inspected snapshot is `pts/phpbench` 1.1.6,
  whose application version is PHPBench 0.8.1, default native argument is
  `-i 2000000`, and `TimesToRun` is 3.
- The original Pure-FTPd PHPBench 0.8.1 source archive is 9,482 bytes. Its MD5
  is `9ee2e4305e320c7f20a3d81978c8d0dc` and its SHA-256 is
  `deff97dd1372405dbad3bf633009ca8446cb9770c5effa40cc45849a461c1b4a`.
  These hashes identify the upstream tarball used by Workshop.
- PTS profile `pts/phpbench` 1.1.6 instead downloads
  `phpbench-081-patched2.zip`. Its `downloads.xml` specifies MD5
  `3e5fa1ad60261ff052bb38f505c8c4e5` and SHA-256
  `32503bd4ace0c8429493de864ca48bb16febed867e52b75f4369d7145f797718`.
  The included compatibility patch was generated by diffing that archive
  against the original upstream tarball. Applying the patch to the pinned
  upstream source produces a file-for-file match with the PTS archive.
  Workshop checks the upstream archive digests and member paths/types before
  extracting it as root, then matches the unpacked tree's paths, file types,
  contents, sizes, and modes against the archive. Its manifest records the
  upstream archive identity, patch hash, PHP CLI version/RPM, architecture, and
  every installed source file hash.
- No PTS executable, profile runner, or PTS result parser is used by this
  benchmark. The PHPBench program itself is the native workload.

The PTS compatibility patch replaces removed `eregi` usage with `preg_match`,
avoids a divide-by-zero case, adapts expressions to PHP 8 behavior, and removes
some old self-check assertions. This is a profile-defined change to the native
workload, so the patch is versioned and attached to each build/run's provenance.
The upstream source's permissive license remains in the installed distribution
and the repository's `third-party` directory.

## Parameters and roles

This is a client-only, single-process PHP workload. It has no server, network,
or external dataset requirement. The selected PTS profile has no option axis:
its default `-i 2000000` is the benchmark's effective point.

The Crucible runtime parameter is `iterations`, validated from 50 through
10,000,000 and passed as a single argv item to `phpbench.php -i`. Its default is
2,000,000. PHPBench's `-i` value is work performed inside one sample. The
profile's `TimesToRun=3` maps to run-file `num-samples=3`; it is not a second
benchmark parameter or a Workshop input.

Workshop installs `php-cli`, applies the pinned source patch, lints each PHP
file, and stages the complete source under
`/opt/crucible/software/bench-phpbench/0.8.1`. Runtime verifies the prepared
tree and PHP binary against the Workshop manifest before executing it. It does
not download, patch, or build at measurement time. Initial support is limited
to x86_64 until the source build and workload have been verified on another
architecture.

Workshop and runtime remove ambient `PHPRC` and `PHP_INI_SCAN_DIR` before
invoking PHP. This leaves PHP's normal compiled default `php.ini` lookup and
additional-INI scan directory active; the client does not use `php -n`, which
would disable that configuration. The build manifest records the resolved
loaded/scanned INI paths and their SHA-256 hashes, all effective INI directive
values, active PHP and Zend module lists, and installed PHP RPM identities.
Before each sample, the client captures the same information under the
sanitized environment and requires an exact match with the Workshop record.
Lint, configuration probes, version checks, and the timed PHPBench invocation
all use that sanitized environment.

The install path avoids collisions with PHPBench's hard-coded global test
search paths. A probe under `/opt/phpbench` executed each test twice because
the same test directory was discovered both as `/opt/phpbench/tests` and as
relative `tests`; PHPBench's summary still said 56 tests. The chosen install
path is not one of those fixed locations, and the adapter requires exactly one
timed output row per source test.

## Results and timing

PHPBench times each test internally and emits one aggregate score:

`round(iterations * 10 / sum(test elapsed seconds))`

The score is an integer, higher is better, and is not a standardized physical
unit. CDM has no `score` metric class; `phpbench-score` uses the supported
`throughput` class because the native value is rate-like, with sum aggregation
across client engines. Average aggregation would divide each sample's score by
the number of repeated-sample metric IDs in the run. Its description states
that the value is the native aggregate score and not a physical throughput
measurement.

PHPBench prints per-test durations but no absolute measurement timestamps. CDM
period timestamps therefore bound the PHP process envelope; they do not claim
to be the native tests' exact measurement interval. The adapter records all
native rows, process timestamps, output hashes, stderr, parameters, source
provenance, and PHP version. Post-processing reparses stdout and confirms the
requested iteration count, all expected test names exactly once, summary score,
and manifest agreement before emitting a metric.

The Crucible runtime helper estimates 37 seconds for the default 2,000,000
iterations from a captured full-profile probe and scales linearly for other
work counts. It returns that estimate without padding; current Rickshaw code
adds 180 seconds to the estimate for its roadblock. The client starts one
whole-client deadline before prepared-image verification: estimate plus 90
seconds. It stops native work by estimate plus 75 seconds, reserving 15 seconds
for process-group shutdown and output capture. The actual `communicate()` wait
is reduced by time spent in preflight. Even after the cleanup reserve, this
leaves at least 75 seconds before the Rickshaw roadblock over the full supported
range: 91/127/275 seconds for the client at minimum/default/maximum iterations,
versus roadblocks of 181/217/365 seconds.

The client queues SIGINT and SIGTERM received during `Popen()` and registration
of the new process group, then handles them through the same final cleanup path
as exceptions and timeouts. Cleanup checks live process-group members even when
the direct leader has already exited, escalates from TERM to KILL, and retains
captured stdout/stderr in the invalid sample manifest. Local tests cover the
launch handoff, timeout diagnostics, and exited-leader descendants; they do not
establish behavior under an actual Crucible roadblock or SUT signal.

The pinned source emits a PHP 8 warning from `test_switch.php`; the initial
AlmaLinux 9.8 / PHP 8.0.30 source probe still completed normally. Stderr is
retained and shown in the validation record; a PHP fatal/parse error or a
nonzero process exit fails the sample.
